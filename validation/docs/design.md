# Translation validation: design

Checks that the generated µSail model (`base.v`, `machine.v`) behaves like Sail's CHERIoT model:
run the same short programs in both, compare the states.
Not implemented yet; this records the choices and the options considered.

## Starting point

- Katamaran's semantics is relational: `Step`, `Steps`, `ForeignCall` are inductive relations. `eval` (expressions) is a function; there is no statement interpreter (only the unbuilt `theories/Staging/CommandStep.v`).
- The generated model leaves memory, tag and fetch reads and platform settings unconstrained (foreign calls); no in-scope code reaches an `undefined_*`.
- Reference: Sail's C emulator for CHERIoT (`cheriot-sail`: `gmake csim`, with `--trace`); also an RVFI-DII build (`cheri_riscv_rvfi_RV32`).

## Decisions

### What is compared

- **Chosen**: the state after each step of a short program, both sides started from reset (`init_model`).
  - State: all registers (capabilities, CSRs, PC) and memory writes.
  - Emulator: state = reset state + the writes `--trace` prints per step.
- Considered:
  - *whole traces only*: compare at the end; a divergence is harder to localise.
  - *per function* (`execute_ADD(args)` against Sail's interpreter in libsail): fine-grained, but not the C emulator, and misses fetch, decode and `step`.
  - *one step from an injected state*: the C emulator has no interface to load a full state (needs a patched `riscv_sim.c` or RVFI-DII tricks).

### How µSail runs

- **Chosen**: a fuel-based interpreter in Rocq, run with `vm_compute`:
  ```coq
  exec : nat -> Stm Γ τ -> State -> CStore Γ -> Outcome (Result τ * State)   (* Done | OutOfFuel | NoAnswer *)
  ```
  - Generic over any Katamaran program, so it can move to Katamaran later.
  - Later: soundness, `exec n s σ δ = Done r -> Steps ...`.
  - Later: extract it to OCaml for a fast µSail simulator and a full test rig (TestRIG-style random sequences).
- Considered:
  - *extracted interpreter first*: fast, but trusts extraction and costs more set-up before the first result.
  - *tactic-driven `Steps` proofs* (`econstructor` per test): the relation itself, but slow and brittle.

### Unconstrained values

- **Chosen**: the harness answers foreign calls from its own model:
  - a concrete memory and tag map in the interpreter's state (fetch, loads, stores, tag operations);
  - platform settings: the emulator's configuration constants;
  - externs with a generated `semantics_*` term: that term, so it is tested too.
- Sound for testing: `ForeignCall` allows every value for an unconstrained call, so a passing run is a real µSail execution.
- Considered: *replay a log of the emulator's extern results*: exact by construction, but needs emulator instrumentation and does not check memory writes against later reads.

### Test inputs

- **Chosen, first**: hand-picked programs, one per instruction class, generated by a script:
  - `ADDI`, `LUI`, `ADD`, `MUL`, `BEQ`, `JAL`, `LW`/`SW`, `CSRRW`;
  - then CHERIoT: `CIncAddr`, `CSetBounds`, `CLC`/`CSC`, `CJALR`.
- Then: traces of `riscv-tests` (`rv32ui`, `rv32um`); random encodings once the interpreter is extracted.
- Considered:
  - *`riscv-tests` traces first*: broad at once, but the trace may not show the full capability and CSR state.
  - *RVFI-DII sequences*: TestRIG-compatible from the start; unclear how much capability state RVFI reports.

### Known divergences

- **Chosen**: *expected-divergence* cases, listed in one table, so a change in behaviour shows up.
  - RV32E register >= 16: µSail fails (`stm_fail`) where Sail traps illegal; the case asserts exactly that.
- Excluded features (PMP, Sv32): no cases.
- C and Zb\* encodings: must trap illegal in both; the emulator is configured as `tests/cheriot/scope.toml` (`--disable-compressed`, PMP count 0, no Zb\*).
- Considered: *skip such cases*: simpler, but the divergence is no longer checked.

### Where it lives, how it runs

- **Chosen**: `validation/` in sail-backend, run by `gmake validate`; `coqc` verdicts cached as for e2e.
- Considered:
  - *Katamaran*: the natural home of the interpreter, but ties the work to Katamaran's review cycle; possible later.
  - *a new repository*: decoupled, but one more repository to keep in sync.

## Open

- Emulator configuration: can `cheriot-sail` be built or run with Zb\* off and PMP count 0? Otherwise those encodings are expected divergences.
- Does `--trace` print full capabilities (tag, bounds, permissions) and every CSR write? Otherwise: a register dump at the end of each program.
- CI: local `gmake validate` first; CI needs the emulator and Katamaran built there.
- `vm_compute` cost of `step` on the generated model (`fundef` size); fuel per step.
